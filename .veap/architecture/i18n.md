# Internationalization (i18n)

Veap supports multi-language setups natively. Global configuration lives under the `intl` key of `veap.config.ts` (`intl.cookie`, `intl.default`, `intl.locales`, `intl.timeZone`).

## Providing Translations

Because Veap is modular, translations must be handled carefully to avoid global dictionary bloat.

1. **Templates**: Templates are responsible for the main application shell dictionaries. They provide translation files inside their `locales/` directory.
2. **Plugins**: Plugins declare their own isolated dictionaries via the `locales` manifest property (a record of locale loaders, e.g. `{ en: () => import("./locales/en"), pl: () => import("./locales/pl") }`), so they remain fully self-contained. When a plugin renders its UI, it uses its own dictionary resolution combined with the globally active locale.

## Best Practices

- Avoid hardcoding text in UI components. Use translation functions or hooks (e.g., `t('button.submit')`).
- Timezones and localized dates should respect the `timeZone` setting defined in `veap.config.ts`.
