# Next.js & UI Integration

Veap uses Next.js (App Router) primarily as a host and renderer, bypassing its standard filesystem routing.

## The Catch-All Route

The entire application runs through `app/[[...catchAll]]/page.tsx` and `app/layout.tsx`.

- Next.js captures the raw HTTP request.
- It passes the URL to `VeapRouter`.
- `VeapRouter` queries the `RouteTree` generated by the `PluginRegistry` to find a matching plugin route.

## Plugin Routing (`routeTree`)

Plugins do not place `.tsx` files in the host's `app/` directory. Instead, they define their own internal directory structure and export a `routeTree` property in their manifest.
Typically, this is generated using the `discoverRoutes` utility, which parses a plugin's internal `src/app` directory and translates it into a virtual route tree format.

## Build Phase & Prerendering

`Application.bootstrap()` skips provider boot when `NEXT_PHASE=phase-production-build` (i.e. during `next build`). Next.js still prerenders `/_not-found` - including the root layout - so the layout and `not-found.tsx` must export `dynamic = "force-dynamic"`. Otherwise request-time helpers (`getPathPrefix()`, `ExtensionPoint`, session cookies) throw "Context is not bound" during prerendering. The `I18nProvider` additionally falls back to the default locale when `cookies()` is unavailable.

## Extension Points & Widgets

Plugins can share UI components without hard dependencies:

- **`ExtensionPoint`**: A global React Server Component wrapper. E.g., `<ExtensionPoint target="app" point="before-content" />`. Any plugin can inject its component into `before-content` by declaring it in its `extensions` array.
- **`Widget`**: Similar to extensions but optimized for dashboard panels, containing metadata like priority and size.
